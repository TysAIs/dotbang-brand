# AGENTS.md — how agents use this repo

This repo is the dotBANG brand law. If you are an agent (Hermes fleet, Muse, or any other) doing design, build, content, or document work for dotBANG or a dotBANG client deliverable, this file governs how you work.

## Before you start

1. **Read `BRAND-GUIDELINE.md` in full before any dotBANG design or build work.** Not a skim: the section for your surface, plus the foundations (logo §§4–5, colour §6, type §§7–9, voice and naming §16). Work started without the guideline gets redone.
2. Check `brand-board-v2.html` for the rendered system when you need to see how the rules look applied.
3. Use the font files in `fonts/` exactly as shipped. Inter and JetBrains Mono, self-hosted. Never substitute a system stack where the guideline requires the brand fonts; the documented fallback tails are the only exception.

## What is law

- **Palette, typography, the mark, spacing, naming, and voice are law**, not inspiration. The guideline gives numbers; use the numbers.
- **Locked templates (marked † throughout the guideline) come first**, the spec second, your taste never.
- **Naming:** the brand is written exactly `dotBANG`. Legal entity: `dotBANG LLC`. Handles and domains follow the guideline's naming section.
- **Privacy standard:** never publish the owner's personal information — no real names beyond what the guideline itself carries, no emails, no addresses, no real IPs or hostnames. Public examples use placeholders and IETF documentation ranges.

## Conflicts and gaps

- **If the guideline conflicts with a task brief, the guideline wins on every brand question.** Do the work the guideline's way, and flag the conflict to Tyler in your report. Do not silently follow the brief, and do not silently override the guide either — flag it.
- **If the guideline does not cover your surface, that is a defect in the guideline.** Stop, ask the owner, and get the answer written into the next version. Improvising a new house style is the one unforgivable move.
- **Exceptions** need the owner's written approval before the work ships, and apply to that one deliverable only.

## Handling

- This repo is **private**. Never copy its contents into a public repo, post, or example. Never make it public. Access is granted per project by the owner; having access for one project does not carry to others.
- When a project repo needs the brand, link back to this repo as the source of truth rather than vendoring drifting copies of the guideline into the project.
