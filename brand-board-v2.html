The mark

the .! idea / made literal

The logo is the punctuation the name plays on: a perfectly round dot, then a very square exclamation point. The dot is always accent blue at full saturation, so the mark carries the brand color everywhere it goes. The exclamation is built from two squares: a block stem and a square point, sharing one width and one baseline with the dot. Nothing is rounded except the dot. Nothing is angled. It reads at favicon size and at billboard size.

Construction: one baseline, one cap line. The bang stem and point share a width; the dot diameter is just under twice that width.

Geometry, frozen

  • Dot: a true circle. Never an oval, never a rounded square.
  • Bang: stem and point are hard squares with zero radius. The point is a square, not a second dot.
  • Color: dot is #6CACE4 at full saturation; the bang is white. No gradients, no alpha washes on the mark.
  • Clear space: one dot diameter on every side. Nothing enters it.
  • Minimum size: 16px tall on screen, 6mm in print. Below that, use the dot alone.
  • Never: recolor the dot to any other hue, outline the mark, add a shadow, rotate it, or set it on a busy photograph.

The mark at size

Favicon legibility is a design requirement, not a hope: two shapes, one baseline, no detail to lose.

Palette

three colors / no exceptions

The system has exactly three colors. Everything else on screen is one of them at an alpha. Targets for any given surface: about 70 percent pitch black, 25 percent white, at most 5 percent blue. The blue share is a ceiling, not a target to hit with decoration: it is spent on the mark, key rules, active states, and hover, where it means something.

The presence rule: blue is never absent, never loud

  • At rest, every screen carries the mark with its blue dot, plus at least one more deliberate blue element: a key rule, an index numeral, an active state, a live indicator.
  • Blue means something. It marks the brand, the current place, or the live thing. If a blue element means nothing, it comes out.
  • Full saturation, always. A pale or washed blue is a bug, not a variant. Alpha is allowed only in glows and shadows, never in the element itself.
  • Never: blue body text, blue section backgrounds, blue gradients, a second accent color, or blue scattered as decoration to fill space.
03

Typography

two families / one scale

Two families, self-hosted as subset WOFF2, pinned to exact versions, identical on every machine. Inter carries the voice; JetBrains Mono carries the data. Version 1.0 set type in system stacks, which meant a different typeface on every platform. That drift is why these files exist. Sizes come from one modular scale, ratio 1.333, snapped to whole pixels and frozen as tokens. Nobody sets a font size that is not on the scale.

primary / inter

Systems that ship

Inter variable, weights 100 to 900 with an optical size axis, served as one 63.7KB Latin subset. Headlines and display at 700 to 800 with tight tracking. Body at 400 to 600, line height 1.65. The system stack survives only as the fallback tail.

data / jetbrains mono

218 variants / 131K

JetBrains Mono variable, one 23.4KB Latin subset. Numbers, tables, labels, coordinates, the ASCII field. Its x-height matches Inter within 1 percent, so inline code and IDs never change visual size. Tabular figures wherever numbers line up in columns.

Casing rules

  • The name is written dotBANG. Lowercase dot, uppercase BANG, in every context, including headlines and all-caps labels. Never set it in all caps; never split it across lines.
  • Headlines: sentence case, tight tracking, no period unless the line is a full statement.
  • Labels: uppercase, 11px, letter spacing 0.18em. Labels are the only all-caps text besides acronyms.
  • Buttons: sentence case, weight 700. No uppercase buttons.

Weight and contrast discipline

  • Thin weights vanish on black. Nothing below weight 400 at text sizes; display never below 750.
  • Dim white (58%) is the floor for reading text. Faint white (36%) is for large or decorative text only, never paragraphs.
  • Tracking tightens as size grows: -0.045em at display, -0.02em at card titles, 0 at body.
  • Never: a size off the scale, a third family, or italic display type.

Liquid glass

chrome and priority panels / only

Glass is the chrome material: headers, footers, and the one panel per view that matters most. Everything else is solid. Glass is spent where it shows and nowhere else, because blur is the most expensive pixel on the page. The specimens below are live: the field behind them is the real ASCII canvas.

The ASCII field

signature background / ambience, not content

The topographic character field from Board A is the signature texture: layered sine contours that read as slow terrain drift. It is atmosphere. It never carries information, never sits under body text at reading contrast, and never responds to the pointer. The frame below is not a picture of it: this whole page floats over the live field.

live sample / the field itself, framed

The glyph ramp

.·:;+*x#%@

Ten glyphs, sparse to dense. Contour banding over layered sine waves makes the terrain. The ramp is frozen: no emoji, no block characters, no second set.

Field rules

  • One canvas per page, fixed behind everything, pointer-events off. Cell 15px, glyph 11px mono.
  • Alpha 0.05 to 0.22, white only. The field is dimmer than the dimmest text. It never takes the blue.
  • Throttled to about 10 frames per second and paused when the tab is hidden. Ambience should cost almost nothing.
  • Reduced motion gets one static frame. No exceptions, no toggle buried in settings.
  • Never: dithering, interactive ASCII, ASCII logos, or ASCII under paragraphs. If text sits on it, the text sits on a panel.
06

Spacing and grid

8pt grid / tokens, not numbers

Every margin, padding, gap, and component size comes from the 8pt scale, the same convention Material, Carbon, and Spectrum run on. Designers and developers use token names, never raw pixel values, so a spacing decision is made once and reused everywhere. Four-point steps are allowed only inside small components: chips, badges, table cells.

  • Layout grid: 12 columns, 24px gutters, content max width 1280px. Page margins 32px on desktop, 24px on phone.
  • Section rhythm: 96px between sections on desktop, 64px on phone. More space above a heading than below it: a new section announces itself with air.
  • Component heights land on the grid too: header bar 58px, buttons 40 to 48px, table rows at 8pt padding steps.
  • Never: a spacing value off the scale (13px, 22px, 7px gaps). If it is not a token, it does not ship.

Radius scale

Performance is a design rule

  • Self-hosted WOFF2 only. One variable file per family, subset by unicode-range: 63.7KB sans, 23.4KB mono on a Latin page, cached immutably. font-display swap over a metric-matched fallback, so a swap never reflows a table.
  • Blur budget: at most 3 backdrop-blurred surfaces in any viewport.
  • One canvas, throttled. The field runs at about 10fps and pauses offscreen.
  • Motion is compositor work: transforms and opacity only, 0.18s ease on states. Nothing animates layout.
